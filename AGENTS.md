# AGENTS.md — FunSync Player (fork)

Local desktop video player that plays funscripts on stroker and vibration devices (Buttplug/Intiface, TCode serial/UDP/WebSocket), with a web remote and a VR content server for HereSphere/DeoVR. `README.md` is the feature documentation: every user-visible feature has a section there, so update it with each change.

## Repository and remotes
- `fork` = `EricTheRed241/funsync-player` (ours, public). `origin` = `DaveMakesWaves/funsync-player` (upstream). **Never push to `origin`.**
- Work on a branch from `fork/main`, preferably in a worktree: `git worktree add ../funsync-<topic> -b <type>/<topic> fork/main`, then symlink `node_modules` from the main checkout and reuse `backend/.venv`.
- Open the PR against `fork` `main` (`gh pr create --repo EricTheRed241/funsync-player`), merge it with a merge commit, then fast-forward local `main` and remove the worktree. When the change touches anything a scheduled job runs (`scripts/`, `crates/`, `renderer/js/`, `electron/` modules the CLIs import, `deploy/k8s/`), run `npm run k8s -- build` in the main checkout afterwards (and `npm run k8s -- apply` when `deploy/k8s/` manifests changed).
- Branch prefixes in use: `feat/`, `fix/`, `docs/`. Commit subject: `<area>: <what>` (e.g. `eroscripts:scout: …`, `preview-check: …`).
- `notes/` (planning docs, `notes/CLAUDE.md` test-environment notes) and `.claude/` are gitignored and may not exist in a checkout.

## Architecture
| Part | Where | Notes |
|---|---|---|
| Electron main | `electron/main.js` | Owns `config.json` (`electron/store.js`, electron-conf), IPC, window, starts the backend; single-instance lock |
| Library scan | `electron/library-scan.js` | Pairs videos with funscripts, variants, axis companions; no Electron dependency, shared with CLIs |
| EroScripts client | `electron/eroscripts-api.js` | Discourse API, attachments, pixeldrain listing, downloads (forum host only) |
| Renderer | `renderer/` (`js/`, `components/`, `styles/`, `locales/`) | ESM inside a CommonJS package; UI strings go through i18n (`data-i18n*`, `t()`), with every locale file updated |
| Backend | `backend/` (FastAPI, Python 3.13, `backend/.venv`) | Port **5123**; `routes/` (media, remote, vr_api, …) and `services/` (vr_sections, library_edits, funscript, …) |
| Web remote | `backend/web-remote/` | PWA served at `/remote/` |
| CLIs | `scripts/*.mjs` | `eroscripts:sync`, `eroscripts:scout`, `faptap:scout`, `dedupe:scenes`, `upgrade:axes`, `prune:generated`, `eroscripts:preview-check`; the two scouts share `scripts/discovery-io.mjs` (config lock, library walk, their download folder as a library source; they never touch playlists) and run `dedupe:scenes --apply` after downloads (`scripts/scene-dedupe-lib.mjs`: same video → one copy kept). New CLIs are Rust (next row) |
| Rust CLIs | `crates/<name>/` (Cargo workspace, root `Cargo.toml`) | `video:tags` (`crates/video-tags`): writes `<userData>/video-tags.json`, which the app merges into `library.scriptTags` after each scan (`renderer/js/video-tags.js`, on top of the post tags, `addedTags`); its `host` module is the Rust side of the host env (userData, backend URL, locks) the other crates use. `pornstar:tags` (`crates/pornstar-tags`, uses the `video-tags` lib for config, atomic write, rescan): recomputes `<userData>/pornstar-tags.json` (performer tags per video, scene counts, applied at `minScenes`) from the library on every run; the same merge unions it with video-tags.json and allows its applied tags. `age:screen` (`crates/age-screen`): weekly underage screener; ffmpeg contact sheets judged by an `omp` run (`--judge-cmd` replaces it), then 1★ / "Underage review" playlist through the running app's remote API; state `<userData>/age-screen.json`, lock `age-screen.lock`, thresholds `ageScreen` in `content-preferences.json`. `scout:report` (`crates/scout-report`): judgments page on port 5131, loopback by default, every interface with `--lan` (no login) over the EroScripts scout's state, waiting list and rejected scenes; verdict records carry `title/author/created/bumped/image/images` (`markTopic` / `postInfo`, `eroscripts:scout --titles` for old ones). Its swipe deck (`/swipe`, waiting posts by score, shows the candidates' `tagScores` / `creampie` the scout computes) writes `<userData>/eroscripts-scout-swipes.json` (right = wanted, taken by `--fetch --auto`; left = hidden from the deck only); its SLR tab deals waiting posts with an SLR video (swipes into the EroScripts file; `eroscripts:scout --fetch` downloads them from SLR, `scripts/slr-host.mjs`) and `<userData>/slr-scout.json` scenes (swipes into `slr-scout-swipes.json`, by SLR scene id). `slr:scout` (`crates/slr-scout`): SexLikeReal VR scenes of the `slrScout` performers (actors + favourites + the pornstar list), scored like `candidateScore` plus SLR bonuses, and the account's download quota, into `slr-scout.json`; `--fetch` downloads the SLR tab's right swipes (video + script from a free EroScripts post, else SLR hand-crafted, else AI) into `Other/`; HTTPS through `curl`, `--login` drives a headed Chrome over CDP (reCAPTCHA) and saves `<userData>/slr-session.json` |
| Scheduled jobs | `deploy/k8s/` (Docker Desktop Kubernetes, kubeadm mode, namespace `funsync`) | One CronJob per recurring CLI (`eroscripts-scout --daily`, `pornstar-tags --apply`, `age-screen --weekly`, `eroscripts-sync`, `faptap-scout` suspended) in the image `funsync-runner:current` (`deploy/k8s/Dockerfile`, entry `run-job`: exit 2 = success). Pods mount the library and userData at their Mac paths and reach the native app as the Service `funsync-app` (ExternalName → `host.docker.internal:5123`). `npm run k8s -- build | apply | run <job> | pause | resume | status | logs <job>`. **After merging a change a job runs, `npm run k8s -- build`** (from the main checkout): jobs run the image, not the checkout |
| App autostart | `deploy/macos/app-autostart.sh` | `npm run app:autostart -- install` (from the main checkout): LaunchAgent `com.funsync.app` starts Electron at login and after a crash; the app restarts its backend itself (`python-bridge.js` auto-restart) |
| omp auth broker | `deploy/macos/omp-broker.sh` | `npm run omp:broker -- install`: LaunchAgent `com.funsync.omp-broker` runs `omp auth-broker serve` on `127.0.0.1:8765`; the age-screen pod's omp is a broker client (Service `omp-broker`, Secret `funsync-omp` = broker token + model roles). Pods never mount `~/.omp` |

Invariants:
- **The desktop app owns the library.** The backend keeps view-only copies registered by the desktop (`POST /api/media/register`). Edits from the phone or headset go through `services/library_edits` and are applied by the desktop. CLIs write `config.json` only while the app is closed (`appRunning` in `scripts/discovery-io.mjs`: `SingletonLock` in userData; one from another host counts as running), or they write side files the app merges (`eroscripts-links.json`, `video-tags.json`, `pornstar-tags.json`). **`FUNSYNC_CONFIG_READONLY=1` (set in the jobs image) means never write `config.json`.** Host env every CLI honours (`scripts/host-env.mjs`, `crates/video-tags/src/host.rs`): `FUNSYNC_USER_DATA`, `FUNSYNC_BACKEND_URL`, `FUNSYNC_CONFIG_READONLY`, and for the VRBangers browser `FUNSYNC_CHROME_PATH` / `FUNSYNC_CHROME_PROFILE` / `FUNSYNC_CHROME_NO_SANDBOX` / `FUNSYNC_VRB_CREDENTIALS`; flags win over env, env over defaults. Run locks are `<pid>@<host>`: a lock from another host is held until 12 h old, never judged by pid.
- Backend networking: binds `0.0.0.0` by default; `--local-only` / `FUNSYNC_LOCAL_ONLY=1` binds `127.0.0.1`. The TCode serial relay (`routes/tcode_relay.py`) lets a web-remote tab drive a USB device with Web Serial, which needs a secure page: plain `http://<ip>:5123` works only with Chrome's `--unsafely-treat-insecure-origin-as-secure` flag on that laptop (user's choice, 2026-11-12; no HTTPS listener yet).
- Axis files are `<stem>.<axis>.funscript` (`AXIS_SUFFIXES` in `library-scan.js`). Generated companions are `<stem>.generated.<axis>.funscript`. **Hand-made axes always win**: generators skip folders with hand-made axes.
- Paths stored in config must use the filesystem's own spelling (Unicode NFC/NFD), because playlists and the headset match scan paths byte for byte.
- Skip AppleDouble sidecars (`._*`, see `isAppleDoubleSidecar`) in any directory walk.
- **Video and script preferences live in `renderer/js/content-preferences.js` only** (exclusions, animated / live rules, minimum length, feeds, FapTap focus, favourites, ranking, quality caps, dedupe keep order, rating thresholds, default sort and score bands, smart playlists, artist-playlist threshold, artist aliases (`ARTIST_ALIASES`, applied through `canonicalArtist` in `renderer/js/artist-playlists.js` by the app and both scouts), auto categories and collections, underage screener, play-queue auto-fill). Libraries import values from it; don't add rule constants elsewhere. **`renderer/js/content-preferences.json` is the shared part of the preferences**: the values Rust reads too (`ageScreen`, `ratings.deleteAtOrBelow`, `pornstarTags`: the pornstar list with names, aliases, scene phrases and `minScenes`; and for `slr:scout`'s scoring `ranking`, `tagScoreGroups`, `favourites`, `libraryMaxVideos`, `videoCaps`, `animationTags`, `slrScout`; `crates/slr-scout/src/score.rs` mirrors `candidateScore` in `renderer/js/preference-score.js` and pins parity with JS-computed cases: change both together); `content-preferences.js` imports it (`with { type: 'json' }`) and re-exports the values JS uses, Rust embeds it with `include_str!`. Change those values in the JSON. Bump `RULES_VERSION` / `FAPTAP_RULES_VERSION` when a screening value changes. The non-JS copies: `TOP_RATED_MIN` and the score-band thresholds (`SCORE_TOP_MIN` / `SCORE_MID_MIN`) in `backend/services/vr_sections.py`; `DEFAULT_SORT` in `backend/web-remote/sort-default.js` (the PWA can't import renderer files).

## CLI pattern
- Logic goes in `scripts/<name>-lib.mjs` (pure, injectable, tested). The CLI in `scripts/<name>.mjs` does IO only, parses flags, prints usage on `--help`, and uses exit codes 0 / 1 / 2 (rate limited or work left) / 3 (not logged in).
- CLIs that import `renderer/*.js` re-exec once with `--disable-warning=MODULE_TYPELESS_PACKAGE_JSON` (copy the block from an existing script).
- Forum access is read-only and paced (`createPacer`, ≥ 700 ms). Silence electron-log in CLIs (`log.transports.*.level = false`).

## Rust migration (user, 2026-11-04)
- **Rust is the target language for CLIs and their tests**, for lower CPU and memory use. Migrate gradually: write *new* CLIs in Rust, and port an existing `scripts/*.mjs` CLI when it gets a substantial rewrite. Don't rewrite working CLIs just to switch language, and don't leave a CLI half in each language.
- Tests follow the code they test: a Rust CLI gets Rust tests (`cargo test`); JS and Python code keep vitest and pytest until that code itself is ported.
- Out of scope: the Electron app (`electron/`, `renderer/`) stays JS and the backend stays Python.
- **Before porting anything that reads preferences** (both scouts, dedupe, `upgrade:axes`): move the values it reads from `content-preferences.js` into `content-preferences.json` (the shared data file, already loaded by both sides), so they keep a single source. Never copy rule constants into Rust.
- Keep the CLI contract when porting: same flags, `--help`, exit codes 0 / 1 / 2 / 3, the same userData files and `SingletonLock` check, and forum pacing of ≥ 700 ms. Keep the `npm run <name>` entry pointing at the new binary.
- **Layout:** a Cargo workspace at the repo root (`Cargo.toml`, `members = ["crates/*"]`, `Cargo.lock` committed, `/target` ignored). One crate per CLI in `crates/<name>/`: a library (`src/lib.rs`, logic split into modules with unit tests) plus a thin `src/main.rs`, and end-to-end tests in `crates/<name>/tests/` that run the binary (`CARGO_BIN_EXE_<name>`) against temp dirs. The npm script is `cargo run -q --release -p <name> --`. Keep dependencies minimal (no HTTP crate for a local request: `std::net::TcpStream`); format with `cargo fmt`, keep `cargo clippy --all-targets` clean.

## Tests
- JS: `npx vitest run` (`tests/unit/**/*.test.js`, jsdom by default). Node-only tests start with the `@vitest-environment node` header block used in existing tests. Run one file with `npx vitest run tests/unit/<file>.test.js`.
- Python: `cd backend && .venv/bin/python -m pytest` (`asyncio_mode = auto`).
- Rust: `cargo test` at the repo root (all crates; one with `cargo test -p video-tags`), plus `cargo clippy --all-targets`.
- Tests cover behaviour (filters, pairing, precedence, boundaries), not wiring. Never hit the network: fake the forum and hosts, and use temp dirs for scenes.
- Smoke-test CLIs against a copied userData (`--user-data <tmp>`) and a temp folder, never the real `config.json`.

## Environment pitfalls
- Don't run `npm install --ignore-scripts` (or `--no-save` installs) in the main checkout: it leaves `node_modules/electron` without its binary. To repair, extract the cached `electron-v<ver>-<platform>.zip` into `node_modules/electron/dist` and write `node_modules/electron/path.txt` (on macOS: `Electron.app/Contents/MacOS/Electron`).
- `npm start` runs `electron .`. The backend is spawned by the app; `npm run backend:dev` runs it alone.
