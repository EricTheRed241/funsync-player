# AGENTS.md — FunSync Player (fork)

Local desktop video player that plays funscripts on stroker and vibration devices (Buttplug/Intiface, TCode serial/UDP/WebSocket), with a web remote and a VR content server for HereSphere/DeoVR. `README.md` is the feature documentation: every user-visible feature has a section there, so update it with each change.

## Repository and remotes
- `fork` = `EricTheRed241/funsync-player` (ours, public). `origin` = `DaveMakesWaves/funsync-player` (upstream). **Never push to `origin`.**
- Work on a branch from `fork/main`, preferably in a worktree: `git worktree add ../funsync-<topic> -b <type>/<topic> fork/main`, then symlink `node_modules` from the main checkout and reuse `backend/.venv`.
- Open the PR against `fork` `main` (`gh pr create --repo EricTheRed241/funsync-player`), merge it with a merge commit, then fast-forward local `main` and remove the worktree. Scheduled jobs run from the main checkout (job runner, below), so a merged change reaches them once local `main` is fast-forwarded; a change to `crates/job-runner` or `deploy/jobs.json` takes effect when the app restarts (it rebuilds the scheduler at start).
- Branch prefixes in use: `feat/`, `fix/`, `docs/`. Commit subject: `<area>: <what>` (e.g. `eroscripts:scout: …`, `preview-check: …`).
- `notes/` (planning docs, `notes/CLAUDE.md` test-environment notes) and `.claude/` are gitignored and may not exist in a checkout.

Invariants:
- **The desktop app owns the library.** The backend keeps view-only copies registered by the desktop (`POST /api/media/register`). Edits from the phone or headset go through `services/library_edits` and are applied by the desktop. CLIs write `config.json` only while the app is closed (`appRunning` in `scripts/discovery-io.mjs`: Chromium's `SingletonLock` in userData, judged by its pid), or they write side files the app merges (`eroscripts-links.json`, `video-tags.json`, `pornstar-tags.json`). **`FUNSYNC_CONFIG_READONLY=1` (set by the job runner) means never write `config.json`.** Host env every CLI honours (`scripts/host-env.mjs`, `crates/video-tags/src/host.rs`): `FUNSYNC_USER_DATA` and `FUNSYNC_CONFIG_READONLY`; flags win over env, env over defaults. Rust CLIs reach the backend at `http://127.0.0.1:<port from config.json>` unless `--backend` is given. Run locks hold the run's pid and are held while that pid lives.
- Backend networking: binds `0.0.0.0` by default; `--local-only` / `FUNSYNC_LOCAL_ONLY=1` binds `127.0.0.1`. The TCode serial relay (`routes/tcode_relay.py`) lets a web-remote tab drive a USB device with Web Serial, which needs a secure page: plain `http://<ip>:5123` works only with Chrome's `--unsafely-treat-insecure-origin-as-secure` flag on that laptop (user's choice, 2026-11-12; no HTTPS listener yet).
- **Access PIN** (user, 2026-11-16): with `<userData>/access-pin.json` (`npm run access:pin`, `crates/access-pin`; `{version, pin, secret, changedAt}`, 0600) present, every request not from loopback needs the `funsync_access` cookie or `?k=` (token `v1.<exp>.<hex HMAC-SHA256(secret, "v1.<exp>")>`, 30 days; the same format in `backend/services/access_pin.py` and the Rust `video-tags` access module, so one login covers 5123 and 5131). Pages 303 to `/login`, APIs 401, WebSockets close 4401, an unreadable file gives 503. Backend: `routes/access.py` (`AccessGate`, outermost middleware); HereSphere / DeoVR log in from the request body (`headset_access`), and any URL handed to a headset must go through `with_key`: media URLs with `access.token` (day-rounded expiry), thumbnail URLs with `access.thumb_token` (`t1.<hex HMAC-SHA256(secret, "t1.thumbs")>`, backend only, no expiry, opens `GET /api/media/thumb/…` only and never logs a headset in; user, 2026-11-22, so headset thumbnail URLs stay stable). Loopback (the app, CLIs, the job runner's jobs) is always open.
- Axis files are `<stem>.<axis>.funscript` (`AXIS_SUFFIXES` in `library-scan.js`). Generated companions are `<stem>.generated.<axis>.funscript`. **Hand-made axes always win**: generators skip folders with hand-made axes.
- Paths stored in config must use the filesystem's own spelling (Unicode NFC/NFD), because playlists and the headset match scan paths byte for byte.
- Skip AppleDouble sidecars (`._*`, see `isAppleDoubleSidecar`) in any directory walk.
- **Video and script preferences live in `renderer/js/content-preferences.js` only** (exclusions, animated / live rules, minimum length, feeds, FapTap focus, favourites, ranking, quality caps, dedupe keep order, rating thresholds, default sort and score bands, smart playlists, artist-playlist threshold, artist aliases (`ARTIST_ALIASES`, applied through `canonicalArtist` in `renderer/js/artist-playlists.js` by the app and both scouts), auto categories and collections, underage screener, play-queue auto-fill). Libraries import values from it; don't add rule constants elsewhere. **`renderer/js/content-preferences.json` is the shared part of the preferences**: the values Rust reads too (`ageScreen`, `ratings.deleteAtOrBelow`, `ratings.topRatedMin` (scout-report's Free space tab), `pornstarTags`: the pornstar list with names, aliases, scene phrases and `minScenes`; and for `slr:scout`'s scoring `ranking`, `tagScoreGroups`, `favourites`, `libraryMaxVideos`, `videoCaps`, `animationTags`, `slrScout`; `crates/slr-scout/src/score.rs` mirrors `candidateScore` in `renderer/js/preference-score.js` and pins parity with JS-computed cases: change both together; `screening` (excluded words, blocked creators / tags / title words, furry and SFW tags, `minVideoMs`), read by `crates/slr-scout/src/screen.rs` for `vrb:scout` and `pmvhaven:scout`; `vrbScout`, `pmvhavenScout`); `content-preferences.js` imports it (`with { type: 'json' }`) and re-exports the values JS uses, Rust embeds it with `include_str!`. Change those values in the JSON. Bump `RULES_VERSION` / `FAPTAP_RULES_VERSION` when a screening value changes. The non-JS copies: `TOP_RATED_MIN` and the score-band thresholds (`SCORE_TOP_MIN` / `SCORE_MID_MIN`) in `backend/services/vr_sections.py`; `DEFAULT_SORT` in `backend/web-remote/sort-default.js` (the PWA can't import renderer files).
- **Creators (`creator-scout`, `creator-report`), 2026-11-18:** a creator is kept with **one profile confirmed live** (Instagram / Twitch, or a public profile page: OnlyFans, Fansly, Pornhub, X, Reddit, ManyVids, link page, IAFD / Babepedia / Boobpedia / FreeOnes; `profiles` in creators.json; profile pages only at the `high` match); the judge (omp + web_search; `--profiles` in batches of 8 people, one subagent each) only proposes, `crate::profiles` verifies (page answers, its own og:title / title / h1 matches by the verify rule). **Instagram's JSON endpoints are dead (404, and the follow POST answers with HTML and does nothing)**: `--pictures` reads the logged-in profile page (Chrome-like `Sec-Fetch-*` headers, embedded `xdt_api__v1__feed__user_timeline_graphql_connection`); `--follow` clicks Follow in a headless Chrome over CDP (`slr_scout::login` launcher with extra flags, session cookies via `Network.setCookies`). `--profiles` turns favourites (`favourites` + `library.favouriteArtists`), the pornstar list and swiped-yes creators into creators and sets `sources`; the site counts `favourite` / `pornstar` creators as yes unless swiped no. `--follow` follows favourite / swiped-yes creators with the session account, never unfollows. Daily: discover → profiles → pictures → follow → fetch.
- **Duplicates tab (`scout-report`, `crates/scout-report/src/duplicates.rs`), 2026-11-19:** the swipe deck's fifth tab (`stack=dupes`) deals pairs of library videos, VS, by a duplicate confidence (title words by the shared `names` rules in content-preferences.json, lengths, identical script from `/api/media/script/<id>`, `scene-frame-cache.json` frame hashes, same post / artist; PMV / compilation and VR-vs-flat pairs capped) above an adaptive bar (`swipeDeck.duplicates`: `minConfidence`, else the best `target` down to `floorConfidence`). ← / → keep the left / right video, ↑ not duplicates, marks in `duplicate-swipes.json`; **deletion only through the desktop**: `POST /api/duplicates/delete` → backend `POST /api/remote/delete-duplicate {videoId, keepId}` → library edit `delete-duplicate` → `deleteRejectedVideo(path, 'duplicate')` (favourite or not, refused while the kept copy is missing; reason `duplicate` keeps the rest of the post wanted).
- **Swipe-card pictures, 2026-11-19:** every Multi / VR / Flat card naming a creators.json creator (her post, a scene performer = name or alias, or her name as whole words in the title; one-word names ≥ 6 letters) carries `people` (≤ 2) with her best picture, chosen by scout-report (`creators.rs`): most-liked Instagram post (`pictures[].likes`, written by `creators:scout --pictures`), else newest Instagram post, else a profile picture, else `ig-profile.jpg`; never post images. `creators:scout --post-images` fills creator posts' missing `image` (FapTap API thumbnail, EroScripts first image; misses in `postImageMisses`, 7 days). `eroscripts:scout --frames` falls back to a rule34video video's poster (`rule34videoPoster` in `scripts/scout-frames.mjs`) when its frames can't be read.

## CLI pattern
- Logic goes in `scripts/<name>-lib.mjs` (pure, injectable, tested). The CLI in `scripts/<name>.mjs` does IO only, parses flags, prints usage on `--help`, and uses exit codes 0 / 1 / 2 (rate limited or work left) / 3 (not logged in).
- CLIs that import `renderer/*.js` re-exec once with `--disable-warning=MODULE_TYPELESS_PACKAGE_JSON` (copy the block from an existing script).
- Forum access is read-only and paced (`createPacer`, ≥ 700 ms). Silence electron-log in CLIs (`log.transports.*.level = false`).

## Rust migration (user, 2026-11-04)
- **Rust is the target language for CLIs and their tests**, for lower CPU and memory use. Migrate gradually: write *new* CLIs in Rust, and port an existing `scripts/*.mjs` CLI when it gets a substantial rewrite. Don't rewrite working CLIs just to switch language, and don't leave a CLI half in each language.
- Tests follow the code they test: a Rust CLI gets Rust tests (`cargo test`); JS and Python code keep vitest and pytest until that code itself is ported.
- Out of scope: the Electron app (`electron/`, `renderer/`) stays JS and the backend stays Python.
- **Before porting anything that reads preferences** (both scouts, dedupe, `upgrade:axes`): move the values it reads from `content-preferences.js` into `content-preferences.json` (the shared data file, already loaded by both sides), so they keep a single source. Never copy rule constants into Rust.
- Keep the CLI contract when porting: same flags, `--help`, exit codes 0 / 1 / 2 / 3, the same userData files and `SingletonLock` check, and forum pacing of ≥ 700 ms. Keep the `npm run <name>` entry pointing at the new binary.
- **Layout:** a Cargo workspace at the repo root (`Cargo.toml`, `members = ["crates/*"]`, `Cargo.lock` committed, `/target` ignored). One crate per CLI in `crates/<name>/`: a library (`src/lib.rs`, logic split into modules with unit tests) plus a thin `src/main.rs`, and end-to-end tests in `crates/<name>/tests/` that run the binary (`CARGO_BIN_EXE_<name>`) against temp dirs. The npm script is `cargo run -q --release -p <name> --`. Keep dependencies minimal (no HTTP crate for a local request: `std::net::TcpStream`); format with `cargo fmt`, keep `cargo clippy --all-targets` clean.

## Tests
- JS: `npx vitest run` (`tests/unit/**/*.test.js`, jsdom by default). Node-only tests start with the `@vitest-environment node` header block used in existing tests. Run one file with `npx vitest run tests/unit/<file>.test.js`.
- Python: `cd backend && .venv/bin/python -m pytest` (`asyncio_mode = auto`).
- Rust: `cargo test` at the repo root (all crates; one with `cargo test -p video-tags`), plus `cargo clippy --all-targets`.
- Tests cover behaviour (filters, pairing, precedence, boundaries), not wiring. Never hit the network: fake the forum and hosts, and use temp dirs for scenes.
- Smoke-test CLIs against a copied userData (`--user-data <tmp>`) and a temp folder, never the real `config.json`.

## Environment pitfalls
- Don't run `npm install --ignore-scripts` (or `--no-save` installs) in the main checkout: it leaves `node_modules/electron` without its binary. To repair, extract the cached `electron-v<ver>-<platform>.zip` into `node_modules/electron/dist` and write `node_modules/electron/path.txt` (on macOS: `Electron.app/Contents/MacOS/Electron`).
- `npm start` runs `electron .`. The backend is spawned by the app; `npm run backend:dev` runs it alone.
